# A72 — Inventori: Hormati Pengaturan `allowNegativeStock` pada Mutasi Manual & Transfer Outlet
Branch: ag/a72-mutasi-stok-limit
LINGKUP KHUSUS: `packages/shared/src/{stock.ts,stock-transfer.ts,fake.ts}`, `packages/shared/test/{stock.test.ts,stock-transfer.test.ts}`, dan `apps/dashboard/src/app/inventori/{stok,transfer}/page.tsx`, plus catatan permintaan RPC server di `docs/REQUESTS-FOR-CLAUDE.md` (JANGAN ubah `data.ts`, `supabase.ts`, `packages/db`, atau `features.csv`/`wave.csv`/`bugs.md`).

Konteks:
- Pengaturan biaya & aturan (`/pengaturan/biaya`, `data.getOutletSettings()` -> `options.allowNegativeStock`) memiliki opsi `"Boleh menjual walau stok habis (stok jadi minus)"`.
- Saat ini di dashboard maupun `fake.ts`:
  1. `stockPostProblem()` dan dialog `PostDialog` di `/inventori/stok` masih selalu membolehkan `adjust_out` / `waste` sampai stok minus (menampilkan banner kuning `"Tetap boleh disimpan"` bahkan ketika `allowNegativeStock === false`).
  2. `transferProblem()` dan dialog `NewTransfer` di `/inventori/transfer` belum memeriksa batas stok outlet asal ketika `allowNegativeStock === false` saat mengirim barang keluar dari lokasi `kind === 'outlet'` tunggal ke gudang.
  3. `fake.ts` (`postStock` & `createStockTransfer`) belum menolak transaksi keluar yang membuat stok minus ketika `CTX.settings.allowNegativeStock === false`.
- Catatan cakupan server: `0014_stock_manual.sql` (`pos.stock_post`) dan `0024_stock_transfer.sql` (`pos.stock_transfer_create`) belum membaca `outlets.allow_negative_stock`; permintaan penegakan server dicatat di `docs/REQUESTS-FOR-CLAUDE.md`. Untuk transfer *keluar dari gudang* (`kind === 'warehouse'`), karena `listStock()` hanya mengembalikan saldo outlet aktif (bukan saldo gudang), pemeriksaan di klien hanya diberlakukan ketika asal adalah lokasi `outlet` tunggal.
